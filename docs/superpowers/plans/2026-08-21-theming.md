# Theming — Category Palettes, App Accents & Grey-Color Fix — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fix the grey-category bug and add three independent user-facing theming controls: 7 category palettes, per-category color override, and 3 app accent themes (each light/dark).

**Architecture:** The `CAT` module (`js/categories.js`) becomes the single source of truth for category colors — a `PALETTES` map (15 colors each: 7 fixed default slots + 8 hash slots) + a per-category override map, with `colorFor()` resolving override → palette → hash-slot so no name ever falls to grey. The app accent is a two-variable CSS split (`--accent` fill / `--accent-fg` foreground) driven by a `data-accent` attribute; the custom-hue case is computed pre-paint in an inline `<head>` snippet. `settings.html` gains the three pickers.

**Tech Stack:** Vanilla HTML/CSS/JS, no build step, no test framework. Chart.js v4 (CDN) for the donut. Supabase for preference sync. Verification is in-browser.

**Spec:** `docs/superpowers/specs/2026-08-21-theming-design.md`

## Global Constraints

- No build step, no test runner, no linter — verify by serving the folder statically (`python -m http.server 8000` or `npx serve .`) and checking in-browser
- Match existing code style: `js/categories.js` and `dashboard.html`/`log.html` use `var`; `settings.html` uses a `let`/`var` mix (follow what each file already does)
- All 7 palettes: ≥3:1 vs `#1A1A1A` (dark surface) and vs `#ffffff` (light surface), EXCEPT `kawaii` which must have relative luminance ≤0.75 (≥1.3:1 vs white)
- Custom categories store `{name, emoji}` only — no `color` field (color is palette-derived at render time)
- `catOverrides` values are normalized to 6-digit lowercase hex so `+ "40"` alpha-dim in `renderDonutChart` keeps working
- No RLS/policy changes — only additive `alter table` columns in `supabase/migration.sql`
- `occurred_on` is `YYYY-MM-DD`; do not conflate with timestamptz fields
- Don't touch `computeRecommendation`, chart date-range logic, or `isRealSpend`/spend filtering

    function hexToHue(hex) {
      var r = parseInt(hex.slice(1,3),16)/255, g = parseInt(hex.slice(3,5),16)/255, b = parseInt(hex.slice(5,7),16)/255;
      var max = Math.max(r,g,b), min = Math.min(r,g,b), d = max - min, h = 0;
      if (d !== 0) {
        if (max === r) h = 60 * (((g - b) / d) % 6);
        else if (max === g) h = 60 * ((b - r) / d + 2);
        else h = 60 * ((r - g) / d + 4);
      }
      h = ((h % 360) + 360) % 360;
      return Math.round(h);
    }

    function currentMode() {
      return document.documentElement.getAttribute("data-theme") === "dark" ? "dark" : "light";
    }

    function applyAccentTheme(theme, hue) {
      var d = document.documentElement;
      if (theme === "crimson") {
        d.setAttribute("data-accent", "crimson");
        d.style.removeProperty("--accent");
        d.style.removeProperty("--accent-fg");
      } else if (theme === "custom") {
        var h = (typeof hue === "number" && !isNaN(hue)) ? hue : 241;
        var mode = currentMode();
        d.setAttribute("data-accent", "custom");
        d.style.setProperty("--accent", window.accentFor(h, mode, "fill"));
        d.style.setProperty("--accent-fg", window.accentFor(h, mode, "fg"));
      } else {
        d.removeAttribute("data-accent");
        d.style.removeProperty("--accent");
        d.style.removeProperty("--accent-fg");
      }
    }

    function renderPreview() {
      var hue = hexToHue(document.getElementById("custom-accent-color").value);
      var mode = currentMode();
      document.getElementById("accent-preview-fill").style.background = window.accentFor(hue, mode, "fill");
      document.getElementById("accent-preview-fg").style.background = window.accentFor(hue, mode, "fg");
    }

    function renderPalettePicker() {
